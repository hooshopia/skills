# پیاده‌سازی مرحله‌به‌مرحله

## قبل از شروع

1. spec یا تسک رو کامل بخون. اگه `SPEC.md` هست، تسک بعدی رو از فهرستش بردار.
2. کدی رو که قراره تغییر کنه بخون و الگوهای موجود رو پیدا کن: نام‌گذاری، ساختار پوشه، مدیریت خطا، سبک تست. **کد جدید باید شبیه کد قبلی باشه.**
3. تست‌ها رو یک بار اجرا کن تا وضعیت شروع رو بدونی. اگه از قبل خراب‌اند، به کاربر بگو و جدا گزارششون کن.
4. یک برنامهٔ کوتاه (۳ تا ۷ قدم) بنویس و اگه تغییر بزرگه، قبل از ادامه به کاربر نشون بده.

## حین کار

- هر قدم رو کوچک نگه دار: تغییر بده ← تست بنویس یا به‌روز کن ← تست و لینت رو اجرا کن ← ادامه بده.
- برای هر رفتار تازه حداقل یک تست بنویس. برای باگ، اول تستی که باگ رو نشون می‌ده.
- **از محدودهٔ تسک بیرون نرو.** اگه چیز دیگه‌ای دیدی که باید درست بشه، یادداشتش کن و آخر کار بگو.
- وابستگی تازه اضافه نکن مگر لازم باشه؛ اگه اضافه کردی، دلیلش رو بگو.
- راز (کلید API، رمز) رو هیچ‌وقت در کد یا commit نذار.
- اگه گیر کردی (دو تلاش ناموفق برای یک مشکل)، بایست و وضعیت رو به کاربر بگو.

## پایان

1. همهٔ تست‌ها و لینت رو یک بار دیگه اجرا کن.
2. diff نهایی رو خودت مرور کن (مثل `code-review`، کوتاه).
3. اگه کاربر خواسته، با یک پیام commit روشن commit کن.
4. گزارش بده: چه چیزی انجام شد، چه تست‌هایی اضافه شد، نتیجهٔ تست‌ها، و چیزهایی که خارج از محدوده دیدی.
5. اگه `SPEC.md` داره، تیک تسک انجام‌شده رو بزن.
