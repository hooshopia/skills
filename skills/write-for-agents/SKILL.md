# نوشتن برای ایجنت‌ها

ایجنت فقط چیزی رو می‌دونه که نوشتی. دستورالعمل خوب کوتاه، مشخص و قابل‌اجراست.

## CLAUDE.md / AGENTS.md پروژه

از کد واقعی پروژه دربیار، نه از حدس. این بخش‌ها معمولاً کافی‌اند:

```markdown
# <اسم پروژه>
یک خط: این پروژه چیه.

## دستورها
- نصب: …
- اجرای محلی: …
- تست: … (تست تکی: …)
- لینت / فرمت: …

## ساختار
- `src/api/` — …
- `src/jobs/` — …

## قراردادها
- الگوهایی که باید رعایت بشه (مدیریت خطا، نام‌گذاری، لاگ)
- کتابخانه‌های ترجیحی و ممنوع

## نکن
- کارهایی که نباید بشه، با دلیل کوتاه
```

## قواعد نوشتن

- **امری و مشخص:** «قبل از commit، `npm test` رو اجرا کن» نه «تست‌نویسی مهمه».
- **دلیل بیار** وقتی قانون غیرعادیه؛ ایجنت با دلیل بهتر تعمیمش می‌ده.
- **مثال** برای هر چیزی که ممکنه بد فهمیده بشه.
- کوتاه نگه دار: هر خط باید جلوی یک اشتباه واقعی رو بگیره. چیزهایی که ایجنت خودش از کد می‌فهمه رو ننویس.
- قانون‌های متناقض نذار؛ اگه دو قانون با هم برخورد دارن، اولویت رو بگو.

## SKILL.md

- frontmatter با `name` (kebab-case) و `description`. توضیح بگه **چه کار می‌کنه و کی باید استفاده بشه**، با عبارت‌هایی که کاربر واقعاً می‌گه (فارسی و انگلیسی).
- بدنه: هدف، مراحل به ترتیب، شکل خروجی، کارهای ممنوع.
- اسکریپت‌ها و فایل‌های کمکی رو کنار SKILL.md بذار و با مسیر نسبی بهشون اشاره کن.

## بازبینی دستورالعمل موجود

اگه کاربر متنی داده: تناقض‌ها، ابهام‌ها، دستورهای قدیمی (که با کد فعلی نمی‌خونن) و تکرارها رو پیدا کن و نسخهٔ اصلاح‌شده رو کنار فهرست تغییرات بده.
