# کدوم اسکیل؟

کاربر هدفش رو گفته ولی نمی‌دونه کدوم اسکیل به کارش میاد. هدف رو با جدول زیر تطبیق بده، حداکثر دو گزینه پیشنهاد کن و بعد از تأیید کاربر همون رو اجرا کن.

| اگه کاربر می‌خواد… | اسکیل |
|---|---|
| یه ایدهٔ خام رو قبل از کد زدن محک بزنه | `grill-me` |
| از ایده یا گفت‌وگو یک مشخصات (spec) قابل‌پیاده‌سازی بسازه | `to-spec` |
| یک spec یا تسک مشخص رو پیاده کنه | `implement` |
| تغییرات خودش یا یک diff رو بازبینی کنه | `code-review` |
| یک Pull Request گیت‌هاب رو بازبینی کنه | `review-pr` |
| کد شلوغ رو بدون تغییر رفتار مرتب کنه | `refactor` |
| یه باگ رو پیدا و درست کنه | `diagnose-bugs` |
| ساختار پروژه رو بفهمه یا برای یک تغییر بزرگ طراحی کنه | `architecture` |
| با تست‌نویسی جلوتر از کد پیش بره | `tdd` |
| مشکل همزمانی، race condition یا رفتار تصادفی رو پیدا کنه | `race-check` |
| کار امروز رو برای خودش یا نفر بعدی تحویل بده | `handoff` |
| یک مفهوم یا بخشی از کد رو یاد بگیره | `teach` |
| برای ایجنت‌ها دستورالعمل، `CLAUDE.md` یا اسکیل بنویسه | `write-for-agents` |
| متن فارسی (رابط کاربری، صفحه، ایمیل) بنویسه یا اصلاح کنه | `fa-copy` |
| پست کانال تلگرام بنویسه | `telegram-post` |

## قواعد

- اگه هدف چندمرحله‌ایه، ترتیب رو بگو (مثلاً `grill-me` ← `to-spec` ← `implement`) و فقط مرحلهٔ اول رو شروع کن.
- اگه هیچ اسکیلی مناسب نیست، صادقانه بگو و خودت مستقیم کمک کن.
- سؤال اضافه نپرس؛ اگه هدف روشنه، مستقیم پیشنهاد بده.
